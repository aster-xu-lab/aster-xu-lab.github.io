ShardingSphere 分片策略实战：5 种算法怎么选

先看分布需求

分片策略本质是回答一个问题：这条数据该存到哪张物理表？ 选择哪种算法，取决于数据特征和查询模式。本文用 5 种内置算法逐一验证，并给出选型建议。

1. INLINE —— 最灵活，Groovy 表达式

  • 用 Groovy 表达式直接算目标表名，最灵活
  • 适合绝大多数”按某列取模/取值”的场景
  • ⚠ 注意：表达式中别调 Java 对象方法（hashCode/format），ShardingSphere 内置的 Groovy 版本对 Java 21 不兼容

2. MOD —— 直接取模

  • 分片键的值直接取模，语义清晰
  • 适合数字类型的分片键（如自增 id）

3. HASH_MOD —— 字符串先 hash 再取模

  • 对字符串分片键（如订单号、手机号）更均匀
  • ⚠ 必须用 auto-tables 模式（ShardingAutoTableRuleConfiguration），不能手动写 actualDataNodes

4. INTERVAL —— 时间范围月分片

  • 按时间维度分片，月表/日表，适合订单、流水类
  • 真自然月（能处理 28/29/30/31 天），不会错位
  • 时间分片天然扩容：加一张月表就是扩容，不用 rehash 历史数据

5. COMPLEX —— 多列复合分片

  • 适合多维度隔离（如多平台 + 时间）
  • ⚠ 查询必须带全部分片键列，否则拒绝；范围查询需显式开启

选型对照表

算法 分片键类型 表模式 典型场景
INLINE 任意 manual 通用取模/取值
MOD 数值 auto 数字自增 id
HASH_MOD 字符串 auto 订单号/手机号
INTERVAL 时间 manual 月/日表、流水
COMPLEX 多列 manual 平台+时间隔离

小结

选型口诀：

  • 字符串分片键 → HASH_MOD（均匀）
  • 数字分片键 → MOD/INLINE
  • 按时间查 → INTERVAL 月表
  • 多平台隔离 → COMPLEX

重点是先想清楚”业务怎么查“，再决定分片键，而不是先选算法。
