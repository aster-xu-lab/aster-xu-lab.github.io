四大限流算法：固定窗口、滑动窗口、漏桶、令牌桶

一、为什么要懂限流算法

面试官问”Sentinel 怎么限流”，如果你只能答”按 QPS 限流”，就丢了架构题的选型分。能画出四种算法、讲清取舍，才是 P7 该有的水平。

二、固定窗口计数器

原理：每秒一个计数器，到阈值就拒。

优点：实现最简单。
缺点：窗口边界突发——比如限 1w/s，0.9 秒打了 9000，1.0 秒又能打 9000，两秒边界瞬间可能 2w 打进来。不精细。

三、滑动窗口

原理：把窗口切成小格（如 10 格），随时间滑动统计。

优点：缓解固定窗口的边界突发——统计的是”最近一个完整窗口”。
缺点：切得越细越耗内存。是固定窗口的改进，但仍有边界近似。

四、漏桶（Leaky Bucket）

原理：请求进队列（桶），恒定速率流出（如每秒 100）。

优点：平滑突发、突发不超峰——无论进来多猛，出去是匀速。
缺点：无法应对瞬时突发——宁可排队也不让快，强削峰但牺牲即时性。

五、令牌桶（Token Bucket）

原理：按速率往桶里放令牌，请求拿到令牌才放行。

优点：允许一定突发（桶里积的令牌可以一口气用掉），又能平滑均值——突发和平滑的平衡。
缺点：实现比固定窗口复杂一点。

这是主流：Sentinel / Guava RateLimiter 用的就是令牌桶。

六、四种算法对比

算法 平滑 突发 复杂度 评价
固定窗口 差 边界可双倍 最低 最糙
滑动窗口 中 缓解边界 中 固定窗口改进
漏桶 最强（匀速） 不允许 中 强削峰
令牌桶 好 允许 中 平衡，最常用

一句话：固定窗口最糙、滑动窗口改进、漏桶强削峰平滑、令牌桶平衡突发与平滑（最常用）。

七、Sentinel 在订单大促里怎么限

  • QPS 模式（令牌桶思想）：按接口 QPS 设阈值（如订单下单接口限 5w）；
  • 并发线程数模式：控制同时处理线程数（如 300），超了排队/拒绝；
  • 热点参数限流：对单个商品 ID/商家单独限，防一个爆款 key 打满整体。

配合：限流是入口控制”量”，熔断是下游异常”快速失败”，降级是”放弃非核心”。三者一起才是大促保障，别单讲限流。

八、分布式限流

单机限流（本地令牌桶）实现简单，但集群要分布式限流：用 Redis Lua + 令牌/计数，把计数放 Redis 共享。代价是每次请求多一次 Redis 调用，性能和一致性要权衡。

总结

  • 固定窗口：最简单，窗口边界突发；
  • 滑动窗口：切格滑动，缓解边界；
  • 漏桶：恒定速率，强削峰，不支持突发；
  • 令牌桶：允许突发 + 平滑均值，最常用（Sentinel/Guava）；
  • 大促里限流 + 熔断 + 降级一起上，限流只是入口控制量；
  • 分布式限流靠 Redis Lua 共享计数，多一次 Redis 调用。
