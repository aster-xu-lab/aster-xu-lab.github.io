Redis 分布式锁与高可用：三大坑、Redisson、主从哨兵 Cluster

一、分布式锁的基础：SET NX EX

Redis 分布式锁的最基础形态是一条命令：

  • NX：key 不存在才设置（互斥）；
  • EX 30：过期时间（防死锁）；
  • unique_value：持有者唯一标识（防误删）。

三个要素缺一个都有坑。下面逐个说。

二、三大坑

坑 1：死锁——持锁的线程崩溃了，锁永远不释放。解法：加过期时间（EX）。

坑 2：误删别人的锁——线程 A 的锁到期自动释放后，线程 B 拿到锁；此时 A 才执行完，去删锁，把 B 的锁删了。解法：value 存唯一标识（UUID），删除时先校验 value 是自己的再删，而且校验+删除必须原子（Lua 脚本）：

坑 3：锁续期——业务执行时间超过锁的过期时间，锁提前释放，别人进来了。解法：看门狗（watchDog）自动续期。

三、Redisson 怎么解决

Redisson 把三个坑都堵上：

  • Lua 脚本保证加锁/释放原子（防误删）；
  • watchDog 看门狗：默认锁 30 秒，每 10 秒自动续期，业务结束释放——业务没跑完锁不丢；
  • 可重入：同一线程可重复加锁，计数。

我在订单中台把它封装成了 XLock，业务侧只需要声明式调用，锁的续期/释放/重入全交给 Redisson。

四、深水区：主从切换，锁会丢吗

单机/主从 Redis 上有个致命问题：锁写在主节点，主挂了没同步到从节点 → 从节点成为新主，那把锁丢了——两个客户端都可能以为自己持锁，出现并发。

RedLock 的思路：向 N 个独立 Redis 节点（通常 3~5 个）逐个加锁，过半节点成功 + 总耗时 < 锁有效期，才算拿到锁。这样即使某个主挂了，多数节点还持锁，别人拿不到过半数。

但 RedLock 有争议：专家指出它在 GC 停顿、时钟跳跃下理论上仍可能出错，不是银弹。业界主流观点：

单机/sentinel/Cluster 的高可用 + 看门狗续期 + 业务幂等兜底，通常就够。别盲目上 RedLock 增加复杂度。

五、我的诚实选择：幂等兜底 > 强锁一致性

这是我认为最值得分享的判断。我的 SyncTask 引擎用 Redisson（单点/主从），锁靠 watchDog 续期防过期，但真正的兜底是幂等：

  • 任务执行有唯一键/去重表；
  • 执行前二次查库校验状态；
  • 即使锁偶尔异常、重复执行，也会被幂等收敛。

所以我不需要 RedLock 的复杂度——锁丢了靠业务幂等兜底，比追求锁本身的绝对一致更划算。这不是偷懒，是”按场景选型”：任务的正确性由幂等保证，锁只是减少无效并发的优化手段。

六、高可用架构：主从 → 哨兵 → Cluster

分布式锁之外，Redis 的高可用演进要理清：

架构 解决什么 分片 高可用
主从 读写分离 / 备份 ❌ 全量 ⚠️ 主挂手动切
哨兵 自动故障转移 ❌ 不分片 ✅ 自动选新主
Cluster 数据分片扩容 ✅ 16384 槽 ✅ 分片内主从
  • 主从：主写从读，扩展读能力，但主挂了不能自动切换；
  • 哨兵：在主从之上加监控 + 自动选新主，仍不分片——解决”高可用”；
  • Cluster：CRC16(key) % 16384 分槽，数据散到多个分片，每个分片内主从——解决”容量 + 高可用”。

七、脑裂：网络分区下的双主

脑裂：主节点和哨兵网络分区，哨兵认为主挂了，选了新主；但旧主其实还活着，还在接受写入——两个主同时存在，数据可能分裂。

缓解手段：min-replicas-to-write（主节点写前要求至少 N 个从节点同步，否则拒绝写）。旧主在分区时从节点连不上，写会被拒，从源头减少分裂数据。

八、集群的两个重定向

Cluster 里客户端算 CRC16(key) % 16384 得槽号，如果请求发到了不是该槽 owner 的节点：

  • MOVED：槽已永久迁到别的节点——客户端要更新本地槽缓存，重发到正确节点；
  • ASK：槽正在迁移中（数据还没搬完）——临时让客户端到目标节点查一次，不更新槽缓存，下次还要问原节点。

一句话：MOVED = 槽归属变了（永久，更新缓存）；ASK = 迁移中（临时，不缓存）。

总结

  • 分布式锁基础：SET key value NX EX，三大坑 = 死锁（加过期）/误删（唯一 value + Lua 原子删）/续期（watchDog）；
  • Redisson = Lua 原子 + 看门狗续期 + 可重入；
  • 主从切换锁会丢，RedLock 有争议，业界主流 = 高可用 + 看门狗 + 幂等兜底；
  • 我的选择：锁靠 Redisson，正确性靠 幂等 + 二次查库，不上 RedLock；
  • 架构演进：主从（读写分离）→ 哨兵（自动故障）→ Cluster（16384 槽分片）；
  • 脑裂用 min-replicas-to-write 缓解；MOVED/ASK 区分”永久/迁移中”重定向。
