Spring Boot 自动装配：从 spring.factories 到 SyncTask Starter 的 @ConditionalOnMissingBean

一、@SpringBootApplication 拆开看

@SpringBootApplication 是三个注解的组合：

  • @Configuration：标记配置类；
  • @ComponentScan：扫描当前包下的组件；
  • @EnableAutoConfiguration：开启自动配置——这是 Spring Boot 的魔法所在。

二、自动配置怎么加载

自动配置的核心是读取配置类名单 + 条件化装配：

条件注解是自动配置的开关：

  • @ConditionalOnClass：classpath 里有这个类才装配（比如有 RedisTemplate 才配 Redis）；
  • @ConditionalOnMissingBean：容器里没有这个 Bean 才装配（我重点用的）；
  • @ConditionalOnProperty：配置了某个属性才装配。

三、@ConditionalOnMissingBean：让默认实现可被覆盖

这是我的 SyncTask Starter 里最核心的一个注解。SyncTask 引擎有 10 个 SPI 扩展点（TaskStore / LockService / NotifyChannel 等），Starter 给每个 SPI 提供了默认实现（adapter-xxljob / adapter-mybatis / adapter-redisson）。

问题：业务方想用自定义实现替换默认的怎么办？

@ConditionalOnMissingBean 的答案：Starter 里的默认实现标上 @ConditionalOnMissingBean——容器里已经有同类型 Bean 时，默认实现自动不装：

为什么用 @ConditionalOnMissingBean 而不是 @Primary/排除：让接入方零配置覆盖——业务方只要 @Bean 一个同名接口的实现，Spring 发现已有就自动不装默认的，接入方不用写 @Primary、不用排除、不用改配置。

这就是”约定优于配置“的落地：Starter 给默认，业务方按需替换。

四、这套设计的价值

这是 SyncTask”新增一个业务任务从数天降到数小时”的底层支撑之一：

如果要替换某一块（比如把通知从企微换飞书），@Bean 一个实现即可，引擎核心不动。这就是 SPI 可插拔 + Spring 自动装配的结合。

五、一个通用认知：框架是”可插拔”的

把这个设计放大看：Spring Boot 的自动配置本质是**”提供默认 + 允许覆盖”**。

  • 你引入 spring-boot-starter-data-redis，Spring Boot 自动配好 RedisTemplate；
  • 你想自定义，@Bean 一个自己的 RedisTemplate，自动配置的默认就退让（靠 @ConditionalOnMissingBean）。

所以所有 Spring Boot Starter 的核心机制都一样：条件注解决定”什么时候装、装谁”。理解了 @ConditionalOnMissingBean，等于看懂了所有 Starter 的实现套路。

六、和 ShardingSphere 的交叉

我在复习时发现一个有趣的对照：ShardingSphere 也有一套自己的 SPI（SPI.load() 机制），和 Spring 的 @ConditionalOnMissingBean 是同一思想的两个实现——核心不动、扩展可插拔。

Spring 自动装配 ShardingSphere SPI
默认实现 @Bean + @ConditionalOnMissingBean 配置文件声明 + 反射加载
覆盖方式 业务方 @Bean 提供新实现 + 改配置
思想 约定优于配置 依赖倒置 + 扩展点

被问到”SPI 和自动装配怎么结合”，把 SyncTask 的 @ConditionalOnMissingBean 和 ShardingSphere 的 SPI 交叉讲，能体现架构级认知。

总结

  • @SpringBootApplication = 配置 + 自动配置 + 组件扫描；
  • 自动配置：从 AutoConfiguration.imports / spring.factories 读名单 + @ConditionalOnXXX 条件装配；
  • @ConditionalOnMissingBean：容器已有同类型 Bean 就跳过默认——默认可被零配置覆盖；
  • SyncTask Starter：10 个 SPI 默认实现 + @ConditionalOnMissingBean，接入方只写 Handler，其余用默认；
  • 这是”新增任务从数天降到数小时”的底层支撑，也是所有 Spring Boot Starter 的通用套路；
  • 与 ShardingSphere SPI 同一思想：核心不动、扩展可插拔。
