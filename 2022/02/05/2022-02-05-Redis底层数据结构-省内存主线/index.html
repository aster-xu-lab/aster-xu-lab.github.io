Redis 底层数据结构：一条"省内存"的主线

一、五种类型的底层实现

Redis 五种数据类型（String/Hash/List/Set/ZSet）各有底层结构：

类型 底层实现
String SDS（简单动态字符串）
List listpack（压缩列表）→ quicklist 双向链表
Hash listpack → 哈希表（不是链表）
Set 整数集合（intset）→ 哈希表
ZSet 跳表 + 哈希表

两张表放在一起，能看出一条清晰的主线——“数据小用紧凑编码省内存，数据大升级成哈希表/跳表换性能”。这是理解 Redis 内存设计的关键。

二、String → SDS：比 C 字符串聪明在哪

Redis 的 String 不用普通 C 字符串（\0 结尾），而是 SDS，三个核心点：

  1. 显式记录长度：SDS 头部存了长度字段，O(1) 拿到长度，不用 strlen 从头数到 \0；
  2. 预分配：扩容时翻倍预分配，减少频繁 realloc 搬内存；
  3. 二进制安全：能存 \0 在内的任意字节，不依赖 \0 结尾——这是它能存序列化对象、图片字节的前提。

一句话：带长度 + 预分配 + 就地向后扩，避免反复 strlen / realloc 搬内存。

三、listpack / intset：数据小时，把元素塞进一块连续内存

当元素少、值小而整数占比高时，Redis 不用”每个元素一个指针 + 对象头”的通用结构，而是用紧凑编码：

  • listpack（压缩列表）：把多个元素紧凑地连续排布，按实际长度变长编码塞进一块连续内存；
  • intset（整数集合）：全是整数时按类型紧凑排列。

好处：省掉指针和对象头的开销，而且一整块数据能装进一个 cache line，扫描都快。

四、升级：数据大了，O(N) 扛不住就换结构

紧凑编码的问题在它是线性扫描 O(N)——数据少时顺序扫也快，数据大到阈值（如 hash-max-ziplist-entries）后，O(N) 太慢。于是升级：

结构 小数据 大数据（升级后）
Hash listpack 哈希表（O(1)）
Set intset 哈希表（O(1)）
ZSet listpack 跳表（O(logN)）

主线一句话：数据小 → 紧凑编码省内存（O(N) 可接受）；数据大 → 升级哈希表/跳表换性能（O(1)/O(logN) 才 hold 住）。

五、ZSet 为什么用跳表

ZSet（有序集合）最常用的场景是范围查询（zrangeByScore：按分数取一段）。跳表 + 哈希表配对：

  • 哈希表：O(1) 查成员（ZSCORE key member 查分数）；
  • 跳表：O(logN) 按分数排范围。

为什么跳表而不是红黑树？两个理由：

  1. 范围遍历方便：跳表是”多层链表”，从最小值开始按序走天然有序，范围查询友好；红黑树虽也能 O(logN) 查单个，但范围遍历要中序栈，麻烦；
  2. 实现简单：跳表代码比红黑树简单得多，改的范围是局部的，便于维护。

六、一个容易说错的点：Hash 底层不是链表

复习卡里我实测说错过一次：Hash 底层是 listpack + 哈希表，不是链表。Redis 的 Hash 解决哈希冲突用的是链地址法（每个桶一个链表），但那是哈希表的实现细节，Hash 类型的底层结构不是链表——小数据用 listpack，大数据用哈希表。

七、面试加分：为什么这套设计重要

这套”紧凑编码 → 升级”策略，本质是 Redis 用空间换启动内存、用升级换大数据性能的权衡：

  • 小数据（绝大多数场景的 key）：内存是主要成本，紧凑编码能把内存压到极限；
  • 大数据：内存次要，性能优先，升级到 O(1)/O(logN) 结构。

这也是为什么 Redis 官方敢说”内存存储 + 单线程就够”——不是所有数据都吃大内存，而是该省的时候省到位了。理解这条主线，比背每种类型的底层结构名字有价值得多。

八、和我的项目

订单系统的缓存 value 用了序列化对象（String/SDS 的二进制安全正好接得住），Hash 存按字段拆分的用户维度数据（字段多时自动升级哈希表），ZSet 做过排行榜/定时任务按分数排序。理解底层，排”大 key”问题时才知道为什么大 hash 要按字段拆分——一个超大 hash 在单线程下 hgetall 是 O(N)，拆小后才可控。

总结

  • String→SDS（带长度 + 预分配 + 二进制安全）；
  • Hash/Set/ZSet 小数据用 listpack/intset（连续内存省指针），大数据升级哈希表/跳表；
  • ZSet 用跳表：范围遍历方便 + 实现简单，配哈希表 O(1) 查成员；
  • 主线：数据小省内存，数据大换性能——这是 Redis 内存设计的核心权衡；
  • Hash 底层是 listpack/哈希表，不是链表（易错点）。
