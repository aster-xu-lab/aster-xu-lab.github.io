Linux 排查三板斧：CPU、内存、磁盘、端口、日志

一、先看资源：top / free / df

线上出了问题，第一步永远是看资源：

命令 看什么
top CPU/内存占用 TOP、load average（负载）
free -m 内存使用
df -h 磁盘使用
iostat IO

load average 高要分清是 CPU 爆还是 IO 爆——top 看 CPU 占用，iostat 看 IO 等待，定位到是计算密集还是磁盘瓶颈。

二、找进程与端口

命令 看什么
ps -ef | grep java 找进程
netstat -tlnp / ss -lntp 查看端口占用
lsof -i:8080 看 8080 被谁占
kill -9 PID 强杀（慎用，先正常信号）

端口被占是日常最高频问题：netstat -tlnp | grep 8080 找占用进程，确认是不是旧实例没退出。

三、看日志：tail / grep

命令 看什么
tail -f app.log 实时跟踪日志
grep -n "关键字" app.log 搜索
grep -i "error" log | tail -100 最近的错误
cat nohup.out 后台程序日志

排查套路：先 tail 实时看，再 grep 搜关键字，错误日志看最近 100 条——三连快速定位问题点。

四、后台启动

  • nohup：不随终端退出而结束；
  • > app.log：标准输出重定向到日志；
  • 2>&1：错误也重定向到同一日志（容易漏，别写错）；
  • &：后台运行。

五、文件与权限（8 年该会）

  • chmod / chown：权限/属主；
  • ln -s：软链；
  • tar：解压打包；
  • du -sh * | sort：磁盘满了找大文件；
  • Docker：docker ps / logs / exec——docker logs 容器 看容器日志。

六、排查套路：一套完整流程

线上问题定位的标准流程：

先资源、再进程、再日志、最后代码——不要一上来就翻日志，先看整体再聚焦。

七、和我的项目

线上排查我做过不少（ThreadLocal 泄漏、连接池隔离、慢 SQL），这套命令是支撑。最典型的例子：高 CPU 排查——top 找进程 → top -Hp 找线程 → jstack 看线程栈 → 定位代码，一条链走完（下一篇展开 JVM 排查）。

总结

  • 看资源：top / free -m / df -h / iostat；
  • 找进程端口：ps -ef / netstat -tlnp / lsof -i；
  • 看日志：tail -f / grep；
  • 后台启动：nohup java -jar xxx > log 2>&1 &；
  • 排查套路：资源 → 进程 → 端口 → 日志 → 代码，先整体后聚焦；
  • 结合线上真实案例（高 CPU/内存泄漏/慢 SQL）讲，比背命令强。
