Spring IoC 与 Bean 生命周期：AOP 代理到底在哪一步生成

用 Spring 8 年，但 IoC 深处（三级缓存、Bean 生命周期、AOP 代理时机）一直是复习时最容易”答不全”的地方。这篇把骨架讲透。

一、IoC：把创建交给容器

控制反转（IoC）：对象的创建和管理交给 Spring 容器，用依赖注入（DI）把依赖装配好，而不是到处 new。

几个关键点：

  • Bean 创建时机：ApplicationContext 的 refresh() 触发——扫描 → 解析定义 → 实例化。单例 Bean 默认容器启动就创建（饿汉式），原型（prototype）懒加载；
  • 注入方式：构造器注入（推荐）/ setter 注入 / 字段注入。

二、Bean 生命周期：完整的一圈

这是 Spring 面试最容易被”答一半”的问题。完整流程：

最重要的一个点：AOP 代理在 postProcessAfterInitialization 生成——即实例化 + 属性填充 + 初始化都完成后，由 BeanPostProcessor 判断”这个 Bean 要不要代理”，要的话返回代理对象。

这也是为什么很多人困惑”AOP 和初始化谁先谁后”：初始化方法（@PostConstruct）跑在原始对象上，AOP 代理在初始化之后包一层。

三、AOP 原理：反射 + 动态代理

AOP 的实现是反射 + 动态代理，两种代理方式：

JDK 动态代理 CGLIB
前提 目标实现接口 目标无接口（或想代理类）
原理 Proxy + InvocationHandler，基于接口 创建子类继承目标类，字节码增强
代理对象 接口的代理 目标类的子类

Spring 默认：目标类有接口用 JDK 动态代理，没有接口用 CGLIB。Spring Boot 2.x 之后默认 proxy-target-class=true，优先 CGLIB。

通知类型：Before / AfterReturning / AfterThrowing / After / Around（环绕，最常用）。切面五要素：切面 / 切点 / 通知 / 连接点 / 织入。

四、一个关键推论：AOP 代理对象 ≠ 原始对象

因为 AOP 返回的是代理对象，所以：

  • this 调用不走代理：Bean 内部 this.xxx() 直接调原始对象的方法，AOP 切面不生效（这是 @Transactional 自调用失效的根因，后面专门讲）；
  • 注入的是代理：别的 Bean 拿到的是代理对象，切面才生效。

理解”代理对象和原始对象是两个东西”，很多 Spring 的”灵异现象”（自调用失效、异步注解失效）都能解释。

五、BeanFactory vs ApplicationContext

  • BeanFactory：顶层接口，惰性加载（用到才创建）；
  • ApplicationContext：BeanFactory 的增强版子接口，容器启动就初始化单例，还带事件、国际化、AOP 等——日常都用它。

六、一个加分点：单例 Bean 线程安全吗

单例 Bean 本身是”无状态”（只有方法逻辑）则线程安全；如果持有有状态的可变字段（如 HashMap 成员被并发改）就不安全。

结合我的订单系统：Service 都是无状态单例，状态放 DB/Redis，不放 Bean 字段——这就是安全的本质。被问到这个问题，结合项目讲”状态外置”比背定义强。

七、和我的项目

我 8 年都在用 Spring，真正吃透生命周期是在做 自研 Starter 时——要控制 Bean 的装配顺序、要让 SPI 默认实现可被覆盖，就得理解 BeanPostProcessor 和 @ConditionalOnMissingBean 的时机（后面单独讲自动装配）。框架用了很多年，但只有当你需要”自定义装配”时，才会真正理解生命周期。

总结

  • IoC：对象创建交给容器，refresh() 时单例饿汉式创建；
  • Bean 生命周期完整圈：实例化 → 属性填充 → Aware → 前置处理器 → 初始化 → 后置处理器（AOP 代理在这） → 就绪 → 销毁；
  • AOP = 反射 + 动态代理：JDK（接口）/ CGLIB（子类）；
  • 代理对象 ≠ 原始对象，this 调用不走代理；
  • 单例 Bean 线程安全的关键：无状态 + 状态外置。
