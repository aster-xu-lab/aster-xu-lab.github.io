跨域 iframe 里的商品描述：读不到 DOM 时怎么取

商品详情页的正文不在主文档里，而在一个跨域 iframe 中。contentDocument 是 null，选择器再准也读不到。遇到这种情况，常见的错误是「加等待」「换选择器」「开调试协议硬读」。这篇讲我们最后选的另一条路：找到 iframe 背后的公开文档，直接取它，取不到就留空。

一、先确认「读不到」是结构问题

新版商品页把卖家描述放在：

这是跨域 iframe。主文档里的脚本既拿不到 contentDocument，也读不到 contentWindow.document。这不是加载没完成，也不是选择器写错——同源策略决定了它永远读不到。

在这个前提下，继续在 iframe 外面等、重试、换选择器，都是无效动作。正确的第一步是承认：这条路走不通，需要换数据源。

二、iframe 背后是一份公开文档

itm.ebaydesc.com 返回的是卖家描述文档本身。它不需要登录态，也不依赖商品页的会话。只要知道商品 ID，就可以直接请求：

这里有两条硬约束：

  1. 只接受数字 ID。 正则 ^\d{6,18}$ 同时挡住了空值、变体后缀和任意字符串。URL 只用这个校验过的 ID 拼接，不会去请求一个调用方传入的任意主机。
  2. 失败不阻塞导入。 请求异常、超时、非 2xx，全部吞掉，descriptionText 保持空。描述是增强信息，不是商品能否导入的前提。

通用错误页 返回空

实机验收时，一条真实商品取到 3734 字符的描述文本，复核页生成的说明以「商品说明」开头，段落空行保留，后面接「商品参数」，总长 4391 字符。

六、边界

  • 只覆盖 eBay。 其他平台的描述结构不同，不能直接复用这个回退。
  • 依赖 iframe 背后的文档路径。 如果平台改了 itm.ebaydesc.com 的路径或返回格式，回退会失效；失效时保持空，不会污染数据。
  • 没有做频率控制。 每条商品只在主文档没有描述时请求一次，但批量导入时的并发行为没有单独压测。
  • 不是「绕过反爬」。 请求的是公开描述文档，不带账号凭据；主文档该走的会话和验证流程不变。这里只是换了一个能读的数据源。

总结

  1. 跨域 iframe 读不到 DOM 是结构限制，不是等待或选择器问题。
  2. 找到 iframe 背后的公开文档，用校验过的 ID 直接取；失败保持空。
  3. HTML 转文本要保段落和列表，错误壳要识别成空——宁可没有，也不要假数据。
