一套资产，三个宿主：Agent 规则的单一源与生成入口

同一套 Skill、规则和角色，要同时喂给 Claude Code、Codex 和 Cursor。最大的风险不是写不出来，而是三份副本慢慢漂移：改了一处，忘了另外两处，最后每个宿主的行为都不一样。这篇讲我们怎么从「符号链接」换到「共享源 + 生成薄入口」，以及生成器必须守住的几条边界。

一、多宿主就是多份副本

三个宿主各有自己的目录和格式：

宿主 入口 格式
Claude Code .claude/skills/、.claude/agents/ SKILL.md、Markdown
Cursor .cursor/rules/、.cursor/agents/ .mdc、Markdown
Codex .codex/agents/ .toml

一开始最自然的做法是复制。每个宿主一份，改的时候同步。问题是：

  • 同一条规则，三份内容慢慢不一致；
  • 某个宿主里加了新 Skill，另外两个没有；
  • 排查「为什么这个宿主行为不对」时，第一件事是猜它读的是哪一版。

多份副本不是备份，是三个真相。

二、第一版：符号链接

为了消掉副本，第一版用了符号链接：.claude/skills 指向 .agents/skills，.cursor/agents 指向同一份角色目录。

在本机 macOS 上这很好用：改一次，三个宿主立刻看到。

但放到跨平台仓库里，问题很快出现：

  • Windows 上 junction / symlink 的权限和创建方式不一致；
  • Git 切换分支、清理目录后，链接可能变成普通文件或断链；
  • 某些工具在遍历时不会跟随链接，表现为「资产突然不见了」；
  • 打包和路径解析对链接的处理各不相同。

符号链接适合个人本机，不适合作为跨平台仓库的长期契约。真正的单一源，不能依赖文件系统特性。

生成物有几个刻意保留的点：

  • frontmatter 留在入口。 宿主靠它发现 Skill 的名字和描述；正文去共享源读。
  • 正文只有一行指针。 不复制内容，避免出现第二份真相。
  • references / scripts / assets 不复制。 它们仍然只在共享目录里，由相对路径解析。
  • 角色按宿主生成不同格式。 同一份 Markdown 角色契约，生成 .claude/agents/*.md、.cursor/agents/*.md，以及 .codex/agents/*.toml；Cursor 侧显式写 model: inherit。

这样每个宿主都能「看见」资产，但内容只有一个来源。

四、生成器要守住的边界

几条规则比生成逻辑本身更重要：

1. 只写内容不同的文件。 避免每次运行都改一堆时间戳或空白，让 diff 失去意义。

2. 拒绝替换非普通文件。 如果目标位置是目录或符号链接，--write 直接报错，不静默删除。迁移旧链接时单独处理，路径上要明确。

3. 不自动删除未托管资产。 宿主目录里可能有用户自己创建的 Skill 或角色，生成器不认识它们。正确做法是报告 unmanaged 并以非零退出码结束，而不是「清理干净」。

4. 所有生成物带固定 marker。 下一个人看到文件就知道它是生成的，应该改共享源，而不是改这里。

5. 统一换行符。 跨平台仓库里 CRLF/LF 混用会让生成物永远「有差异」，--check 失去意义。

6. 增删或修改 name/description 后必须重新生成。 这两类字段在入口里，正文改了立即生效，但入口变了必须同步。

五、为什么不直接复制正文

复制正文看起来更简单：宿主读自己的文件，不依赖相对路径。但它把「单一源」变成了「单一源 + N 份缓存」，而且缓存没有失效机制。

薄入口的代价是多一次文件读取，换来的是：

  • 正文只有一份，改完立即对所有宿主生效；
  • 入口内容稳定，diff 小；
  • 生成器可以校验漂移（--check）；
  • 宿主格式差异被隔离在入口层，正文不用为每个宿主写一遍。

这个取舍和代码里的「生成物不要手改」是同一个道理。

六、边界与治理

  • 模型、工具、权限不随资产同步。 这些是宿主配置，不是共享资产的一部分。角色文件里写 model/tools 只作为参考，实际启动以宿主配置为准。
  • 读取正文不等于启动子 Agent。 .claude/agents 是原生角色适配；能不能真正委派，取决于宿主注册和权限。
  • .claude/skills 是生成物，不要手改。 改了会在下一次 --write 被覆盖，而且 --check 会报漂移。
  • 宿主发现能力以运行验证为准。 文件存在、格式正确，不代表宿主一定能加载；尤其是 Codex 的 TOML 和 Cursor 的 .mdc，格式错误往往静默失败。
  • 未托管资产不自动删除。 这是保守选择：宁可留下一个孤儿文件，也不要误删用户自己写的东西。

七、总结

「单一源」不是「只有一个文件」，而是只有一个可编辑的文件。

其余的都应该是生成物，并且满足三个条件：

  1. 可重建：删掉之后能由脚本重新生成；
  2. 可校验：--check 能发现漂移；
  3. 可识别：文件里有标记，告诉下一个人不要手改。

多宿主协作真正难的不是格式转换，而是让每个宿主都相信同一份真相。
