让 AI Agent 在真实工程里可控：四层约定分工

让 AI 写代码不难，难的是让它在一周之后、另一个会话里、换一个人接手时，依然按同一套约定干活。这个项目我搭了四层文本约定，把”工程事实”喂给 Agent。这篇文章讲这四层怎么分工。

一、根本问题：Agent 没有长期记忆

每次新会话，Agent 都是白纸。它不知道：

  • 这个仓库的包管理器是哪个；
  • 哪些命令是不能跑的；
  • 品牌名的大小写约定；
  • 采集为什么只能用某一条路径。

人能靠”问同事、翻文档、看历史”补上，Agent 不能。所以唯一能跨会话传递工程事实的东西，就是仓库里的文本。这就是四层约定的由来——不是给 Agent 下指令，是给它事实。

二、四层约定

层 载体 作用 长度
索引层 CLAUDE.md 新会话的入口 + 短索引 很短
硬约束层 AGENTS.md 不变量、命令、依赖规则 长而稳
路径域层 .cursor/rules/*.mdc 按文件 glob 注入的领域细节 中等
能力层 .cursor/skills/ 可复用的操作流程 按需触发

索引层只说”去哪看”和”当前快照在哪”。它刻意不复述细节——因为复述就会漂移。

硬约束层是真正的规则中心：安全边界（Sandbox / IPC）、采集边界、依赖版本钉死规则、命令清单。这里写的东西改得很少，一旦改了就是大事。

路径域层是”你正在碰某个领域的代码时，才需要知道的细节”。比如你要改打包配置，才需要知道”不能在 mac 上打 win 包”。它靠 glob 匹配自动注入——不该看的东西不占上下文。

能力层是操作流程：出包自检、任务环的计数规则、采集清理。它们是”做完某类事应该查一遍什么”的清单。

三、为什么分层，而不是一个大文档

核心资源是上下文预算。不可能每次对话都把整个工程手册塞给 Agent——既贵又稀释重点。分层的本质是按需加载：

  • 索引层永远在（很短的入口）；
  • 硬约束层在涉及代码改动时进来；
  • 路径域层只在你碰相关文件时进来；
  • 能力层只在触发某类任务时进来。

这跟”新人入职”是一样的：你不会第一天就把所有 SOP 塞给他，你会给他一个”找谁、去哪查”的索引，然后在他接手某块时丢对应的细则。

四、最重要的一条纪律：不要两处漂移

同一个事实只写一处，别的地方引用它。

工程里有一条明确的写法：短索引文件里写”完整约定以 AGENTS.md 为准，此处不复述，以免两处漂移”。这不是客套，是经验的产物——两处写同一件事，早晚会一处改了一处没改，然后 Agent（和人）会读到矛盾的信息。

同理，工具的规则文件之间也互相不重复：一件事归属哪层，就在那层写死，其他地方只给指针。

五、写给 Agent 的文档，和写给人不一样

几个具体的差别：

  • 命令要可执行。不写”记得检查一下类型”，写”pnpm run typecheck；pnpm run verify:ready 是 typecheck + lint”。
  • 失败码要具体。不写”打包可能失败”，写”会出现 BUNDLE_PLATFORM_MISMATCH，原因是跨平台打包”。
  • “不要做什么”要显式。人靠常识避开的事，Agent 不一定——所以要白纸黑字：”本项目没有测试框架，不要臆造 pnpm test“、”不要在 mac 上跑 Windows 打包”。
  • 镜像的禁区也要写。比如”某个 UI 库不要整包引入”。

一句话：把”老员工知道但没人写下来”的东西，写下来。

六、门闩：让 Agent 能自检

文档只能告诉 Agent”该做什么”，管不住它”做没做对”。所以还要给它能自己跑的门闩：

  • verify:ready = 类型检查 + lint（只把 error 当失败，warning 不拦）；
  • 改了 preload 之后，光过 typecheck 不够，要用调试协议断言 typeof window.api === 'object'——因为”运行时是不是个对象”类型系统看不出来；
  • 改了打包布局，要跑产物自检，而不能只信构建命令的退出码。

门闩的意义是：Agent 在说”我做完了”之前，有一个能被验证的、客观的标准，而不是靠它自己判断。

七、诚实的边界

  • 四层约定能治”Agent 不守规矩”，治不了”Agent 判断错”——文档里的规则再细，也挡不住它写出语义错误的代码。门闩（类型 / lint / 产物校验）才是一道真实的墙。
  • 这套东西有维护成本：规则会过期，文件会漂移。收益只在长期、多人、多会话的项目里才显出来；一次性小脚本不值得这么搞。
  • 它不是某个工具的专属。约定是”给 Agent 读的工程事实”，换哪个 Agent、哪个编辑器都成立——只是不同工具的文件名不一样（AGENTS.md / 规则文件 / skills 目录）。

总结

  • Agent 没有长期记忆，跨会话只能靠仓库里的文本；四层约定就是给它”事实”，不是”指令”；
  • 四层分工：索引层（短、只指路）/ 硬约束层（稳、不变量）/ 路径域层（按 glob 注入）/ 能力层（按任务触发）；
  • 分层的本质是按需加载，为了省上下文、抓重点；
  • 铁律：同一事实只写一处，其他地方引用，坚决不要两处漂移；
  • 面向 Agent 的文档要可执行、有具体失败码、显式写禁区——把”没人写下来的常识”写下来；
  • 文档管”该做什么”，门闩管”做没做对”：verify:ready、CDP 验 window.api、产物自检不信退出码。
