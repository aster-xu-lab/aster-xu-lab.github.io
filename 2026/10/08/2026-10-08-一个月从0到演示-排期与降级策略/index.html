一个月从 0 到演示：排期与降级策略

从零到招商演示，我给的时间是一周；从零到”能发给商户的生产版”，合理周期是 8–12 周。同一件事，两个数字差十倍。这篇文章讲怎么把”演示版”和”生产版”分开，以及演示交付里最重要的东西——降级方案。

一、先给两个不同的数字

接到”做个桌面端，月底演示”时，最容易犯的错是只用一句话回答。要么拍胸脯”没问题”，要么为难”做不完”。正确的做法是把问题拆成两个范围、两个周期：

范围 可行性 周期
招商演示版（macOS + 固定样例 + 写入草稿箱） 有条件可行 一周
商户生产版（双平台 + 安装分发 + 签名公证） 不可行 8–12 周

一开始就把这两个数字说清楚，是保护项目，也是保护自己。 演示版能过，不代表产品能发；反过来，因为演示版过了就以为”下周能发”，是最危险的误解。

二、冻结 MVP：演示必须完成的清单

演示版的范围要冻结成一份可勾选的清单，比如：

  1. 应用能启动、能登录；
  2. 粘贴至少一条真实商品链接；
  3. 本地引擎打开页面并导出快照；
  4. 抽出标题 / ID / 品牌 / 价格 / 图片 / 属性；
  5. 显示原始值与目标值，标出缺失和冲突，可人工修改；
  6. 确认后调用草稿接口；
  7. 在真实后台看到草稿。

冻结的意思是：过了某个日期就不再新增范围。没有这条，演示前的每一天都会被”顺带加个小功能”蚕食。

三、”明确不做”清单，比”做什么”更重要

演示版的价值，一半在”做了什么”，另一半在”明确没做什么“。要白纸黑字写下来：

  • Excel 导入、批量同步、自动上架；
  • 自动车型推断、AI 补造字段、绕验证码；
  • 断点续传、自动更新、正式安装包、公证、Windows 版；
  • “任意商品都能迁移”的承诺。

“不做”不写下来，就会变成默认要做的——因为没人在会议上反对它。写下来之后，才对”不做的也要写进项目文档”这件事有共识。

四、三级回退：演示的保命符

这是演示交付里最实用的一招——给核心链路准备三级降级：

级别 方案 说明
1 真实引擎实时抓取 → 真实草稿 理想情况
2 加载预先保存的真实页面快照 → 真实草稿 实时抓取受限时的替补
3 加载固定 JSON → 只演示界面与草稿接口 并明确说明抓取链路未通过

这里有一条底线：受限时切到快照，绝不假装实时成功。 演示时如实说”这条用了预存快照”，比”看起来成功了但其实是假的”好一万倍——后者一旦被追问就崩。

五、Gate 与降级

排期不是一条直线，而是一串带退出条件的 Gate：

  • 某天之前，引擎必须能读取两个平台各一个样例；
  • 某天之前，草稿接口必须能返回真实 ID；
  • 某天之前，必须完成三次完整演练并录屏。

每个 Gate 都有明确的退出条件。还有一条我写在计划里的原则，值得原样抄出来：

周末不作为默认承诺；如果关键 Gate 没过，立即把演示降级为”一平台真实 + 一平台快照”，不要靠临时加班掩盖关键依赖。

这句话反的是两种常见病：把”加班”当成解决依赖问题的方案；以及”gate 没过但假装能过”，一路拖到演示当天。

六、每天按四项汇报

汇报格式固定四项，逼自己（和团队）说清楚状态：

  1. 已完成；
  2. 明日目标；
  3. 阻塞项；
  4. 需要领导决策。

第三、四项是重点——阻塞和待决策的事必须每天浮出来，而不是攒到演示前一起爆。

七、诚实的边界

  • 演示版的成功不等于生产可用。演示版可以预装环境、只跑固定样例；生产版要处理任意商品、安装分发、签名公证、Windows——这些是另一次工程。
  • 有几类依赖不在自己的排期内：草稿接口、测试账号、合规样例、证书申请与审核。这些必须在 Gate 里标成外部依赖，并提前推，而不是等着它自己到位。
  • 三级回退是保命符不是遮羞布——它能救一次演示，不能替代”核心链路能不能跑通”这个真问题。

总结

  • 面对”月底演示”，先给两个数字：演示版一周、生产版 8–12 周，把两者严格分开；
  • 冻结 MVP（可勾选清单）+ “明确不做”清单（不写就会被蚕食）；
  • 三级回退：实时抓取 → 真实快照 → 固定 JSON；底线是受限时如实说明，不假装成功；
  • 排期是带退出条件的 Gate；”Gate 没过就降级，不靠加班掩盖关键依赖”；
  • 汇报固定四项：已完成 / 明日目标 / 阻塞项 / 需决策；
  • 外部依赖要标出来并提前推，它们不在你的排期里。
