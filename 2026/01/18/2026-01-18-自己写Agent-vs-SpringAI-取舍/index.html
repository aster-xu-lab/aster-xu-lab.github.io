自己写 Agent vs Spring AI：210 行和 30 行的取舍

定位：学习笔记。同一个 Agent 功能，我写了两遍——一遍自己实现，一遍用 Spring AI。差异本身就是最好的教材。

一、同一个功能，两种实现

我先把 Agent 的核心循环自己实现了一遍（30 行，见上一篇），再用 Spring AI 写了一遍。对比下来：

自己实现 Spring AI
Agent 核心 ~30 行（显式 ReAct 循环） ~8 行（一个方法调用）
LLM 客户端 ~100 行（HTTP + JSON 解析） 0 行（自动配置）
工具注册 ~20 行（ToolRegistry） 0 行（@Tool 注解自动发现）
工具定义 每个 ~30 行（实现 Tool 接口） 每个 ~8 行（加注解）
总计（2 个工具） ~210 行 ~30 行

框架把”元数据（schema）”从你的代码里抹掉了——代价是你不再感知它，好处是开发快一个数量级。

四、其他维度

  • LLM 调用：自己实现用 JDK HttpClient 手动拼 JSON、自己管 role；Spring AI 用 ChatModel 接口 + 类型安全的 UserMessage/AssistantMessage；
  • 上下文管理：自己实现手动维护 List<Message> history 并拼进请求；Spring AI 用 ChatMemory 抽象自动维护；
  • 可移植性：自己实现绑死一个厂商的 API；Spring AI 换一个 starter 就能切 OpenAI、Ollama、Anthropic；
  • 生产就绪：自己实现要自己加日志、监控、重试、限流；Spring AI 有 @Retryable、Observability、Metrics 开箱即用。

五、学习价值：这是两者最大的差距

自己实现 Spring AI
理解原理 高——你能看清每一步 低——只知道调了个 call()
快速开发 低——每个环节自己写 高——几分钟集成
适合阶段 学原理 做项目

这个差距才是写两遍的核心意义。 如果你一上来就用 Spring AI，你只会”调 call()”而不知道循环在哪；如果你一直自己实现，开发效率会被拖垮。

六、我的结论：两者不冲突，是先后关系

Agent 的本质就是 3 行伪代码：

Spring AI 只是把这 3 行藏在了 ChatModel.call() 里面。藏得越多，开发越快，但理解越浅。

正确的路径是：先用自己实现把 ReAct 循环跑明白（懂原理），再用 Spring AI 加速实际开发（快交付）。 我在 agent-demo 项目里就是这么做的——两个模块并存，一个负责”懂”，一个负责”用”。

这也回答了”自己造轮子还是用框架”的老问题：造轮子的目的不是替代框架，而是理解框架。 理解了轮子，用框架时才不会踩进去出不来。

总结

  • 同一功能：自己实现 ~210 行，Spring AI ~30 行；
  • 核心差异：循环显式 vs 隐式——自己实现可见可控，框架自动编排；
  • 工具定义：手写 JSON Schema vs @Tool 注解自动生成；
  • 学习价值差最大：理解原理 vs 快速交付；
  • 正确路径：先手写懂原理，再用框架快交付——两者是先后关系，不冲突。
