MCP：工具调用的"JDBC"——从零看一个 JSON-RPC 协议

定位：学习笔记。MCP（Model Context Protocol）是 2024 年底由 Anthropic 提出的工具调用标准化协议。我为了搞懂它，自己实现了一个最小版 Server/Client。

一、MCP 解决什么问题

在 MCP 之前，每个 LLM 应用连工具都是自己造的轮子：协议自己定、格式自己定、连自己的 Agent 是这套、换一个框架又得重写。

MCP 的定位一句话：工具调用的 JDBC。

JDBC 干的事，是让任何 Java 程序用同一套接口连任何数据库（换个驱动即可）。MCP 干的事，是让任何 LLM/Agent 用同一套协议连任何工具（换一个”驱动”即可）。

二、协议核心：JSON-RPC 2.0 over stdio

MCP 的传输层用 JSON-RPC 2.0，传输通道用 stdio（标准输入输出）。关键就两个方法：

  • tools/list：列出所有可用工具（名字、描述、输入 schema）；
  • tools/call：调用指定工具，传参数，拿结果。

五、MCP vs Agent：两个容易混淆的角色

学习时我一度分不清 MCP 和 Agent 的关系：

MCP Server Agent
角色 工具提供者（被调用） 任务执行者（主动调）
做什么 暴露工具，等待调用 拆任务、做决策、调工具
进程 常驻，等请求 常驻，跑循环

类比：MCP Server 像一个”工具服务”（被调），Agent 像一个”调度大脑”（调用）。Agent 进程是调用方，MCP Server 是被调用方——Agent 通过 MCP 协议拿到 MCP Server 暴露的工具。

六、诚实的边界

我的 demo 只实现了 MCP 的”工具调用”部分（tools/list、tools/call），忽略了资源（resources）、提示词（prompts）等高级特性。MCP 官方协议更完整，还有 Streamable HTTP 等传输方式。但核心骨架——JSON-RPC 请求/响应 + 工具注册——就是上面这几行，看懂了就理解了这个协议的设计思想。

总结

  • MCP = 工具调用的 JDBC，任何 LLM 用统一协议连任何工具；
  • 协议核心：JSON-RPC 2.0 over stdio，两个方法 tools/list + tools/call；
  • 剥开协议外壳，核心还是 Tool 接口 + 注册表，MCP 只是包了层标准化通信；
  • Client 与 Server 通过子进程管道通信，发一行 JSON 等一行 JSON；
  • MCP Server 是”工具提供者”，Agent 是”任务执行者”，角色别混；
  • 概念年代：MCP 2024 年底提出，这篇是 2026 年 6 月的学习记录。
