Spring AI 实战：把 LLM 接进 Java 应用，8 行代码

Java 后端做 AI 功能，Spring AI 是官方首选。这篇用一个完整示例讲怎么把 LLM 接进 Spring Boot 应用——包括最简单的对话、工具调用（Function Calling），以及踩过的版本坑。

一、为什么是 Spring AI

Java 生态接 LLM，两个主流选择：Spring AI（Spring 官方）和 LangChain4j。

  • Spring AI：Spring 官方集成，ChatClient 调模型、ChatClient...call().entity(Class) / StructuredOutputConverter 做结构化输出，跟 Spring 生态无缝；
  • LangChain4j：功能更全，但和 Spring 的集成不如 Spring AI 顺。

Java 后端项目，优先 Spring AI——这正是我 agent-demo 里验证过的结论。

用户说”帮我查一下 ORD-2026-0001 的物流”，模型会输出”调用 queryLogistics，参数 {orderNo: ORD-2026-0001}”，Spring AI 自动执行你的方法，把结果喂回模型再生成回答。

@Tool 的价值：你只写业务逻辑（查物流），方法的签名自动生成 JSON Schema——不用手写 schema，也不用自己管理”模型说要调哪个工具”的循环。

四、结构化输出：让模型返回 JSON 而不是自然语言

很多时候你要的不是”一段话”，而是结构化的数据（比如解析用户的意图）：

Spring AI 的结构化输出用 ChatClient...call().entity(Class)，底层是 StructuredOutputConverter（如 BeanOutputConverter<Intent>）。如果直接拿 ChatModel，可以先 chatModel.call(prompt) 拿到文本，再 converter.convert(text)；没有 chatModel.call(prompt, Intent.class) 这种重载。

注意：结构化输出和 Function Calling 不是一回事。entity() 约束的是回复的数据形状；Function Calling 是让模型声明调用哪个工具。两者可以配合，但不能互相等同。这是让 LLM 成为”可编程组件”的关键一步。

六、踩过的版本坑

Spring AI 版本迭代快，几个坑记录一下：

  1. 依赖要用 starter：要启用自动配置，引 spring-ai-starter-model-anthropic；只引非 starter 的 model 包，ChatModel 不会自动装配进来；
  2. 版本要统一：starter 和其它 Spring AI 模块走同一个 BOM / 版本号，避免混版本；
  3. 别照抄旧版 API：FunctionCallbackResolver 在 1.1.x 已经不存在，工具解析换成了 ToolCallback / ToolCallbacks（以及 ToolCallbackResolver）；网上 0.x 的示例直接复制会编译不过；
  4. WebClient 依赖：Anthropic 的 model 实现内部走 WebClient，要保留 spring-webflux；
  5. 非 Web 应用：如果只是纯调用（无 HTTP 接口），设置 WebApplicationType.NONE 避免起不必要的 Web Server。

七、什么时候该上 Spring AI

  • 你的功能是”LLM 对话 / 调用工具 / 结构化输出” → Spring AI 直接上；
  • 你的项目已经是 Spring Boot → 无脑选 Spring AI；
  • 需要深度编排（多步 Agent、记忆管理） → Spring AI 提供基础，复杂场景可能要自己搭或配合 LangChain4j。

总结

  • Spring AI = ChatModel / ChatClient 调模型 + @Tool 定义工具（显式注册）+ entity(Class) 结构化输出；
  • 对话 8 行、工具调用加个注解并注册、结构化输出声明一个 record；
  • 对比自实现：懂原理（自写）→ 快交付（Spring AI），先后关系；
  • 版本坑：用 starter、版本统一、别照抄旧版 API、保留 webflux、非 Web 应用设 NONE；
  • Java 后端做 AI，Spring AI 是首选。
