Spring AI 实战：把 LLM 接进 Java 应用，8 行代码

Java 后端做 AI 功能，Spring AI 是官方首选。这篇用一个完整示例讲怎么把 LLM 接进 Spring Boot 应用——包括最简单的对话、工具调用（Function Calling），以及踩过的版本坑。

一、为什么是 Spring AI

Java 生态接 LLM，两个主流选择：Spring AI（Spring 官方）和 LangChain4j。

  • Spring AI：Spring 官方集成，ChatClient 调模型、StructuredOutput 结构化输出，跟 Spring 生态无缝；
  • LangChain4j：功能更全，但和 Spring 的集成不如 Spring AI 顺。

Java 后端项目，优先 Spring AI——这正是我 agent-demo 里验证过的结论。

六、踩过的版本坑

Spring AI 版本迭代快，几个坑记录一下：

  1. starter 和 model jar 版本要一致：spring-ai-bom 有已知 bug（${project.version} 引用错误），直接依赖 spring-ai-anthropic:1.1.6 更稳；
  2. 类冲突：不同版本间 FunctionCallbackResolver 有冲突，要统一版本；
  3. WebClient 依赖：spring-ai-anthropic 内部依赖 WebClient，要保留 spring-webflux；
  4. 非 Web 应用：如果只是纯调用（无 HTTP 接口），设置 WebApplicationType.NONE 避免起不必要的 Web Server。

七、什么时候该上 Spring AI

  • 你的功能是”LLM 对话 / 调用工具 / 结构化输出” → Spring AI 直接上；
  • 你的项目已经是 Spring Boot → 无脑选 Spring AI；
  • 需要深度编排（多步 Agent、记忆管理） → Spring AI 提供基础，复杂场景可能要自己搭或配合 LangChain4j。

总结

  • Spring AI = ChatModel 调模型 + @Tool 定义工具 + StructuredOutput 结构化输出；
  • 对话 8 行、工具调用加个注解、结构化输出声明一个 record；
  • 对比自实现：懂原理（自写）→ 快交付（Spring AI），先后关系；
  • 版本坑：starter/model 版本一致、保留 webflux、非 Web 应用设 NONE；
  • Java 后端做 AI，Spring AI 是首选。
