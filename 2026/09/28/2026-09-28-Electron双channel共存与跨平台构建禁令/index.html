Electron 双 channel 共存与跨平台构建禁令

一个桌面应用要同时发”测试版”和”生产版”，两个版本还得能在同一台机器上并存、互不覆盖。这篇文章讲双 channel 隔离要隔离哪些东西，以及 asar 污染和跨平台构建这两个真踩过的坑。

一、为什么需要双 channel 共存

测试版和生产版是两类用户：内部试用 / 商家正式使用。理想情况下，同一台机器上：

  • 两个版本能同时安装；
  • 各自有独立的配置、缓存、数据库；
  • 安装一个不会覆盖另一个；
  • 同 channel 的覆盖升级仍然正常。

要做到这些，”隔离”必须隔离得彻底——半隔离会出很多诡异问题（比如两个版本抢同一个数据库、抢同一个单实例锁）。

二、隔离清单

channel 隔离落在五个地方：

项 生产版 测试版
显示名 / 应用名 App App Test
appId（bundle id） com.company.app com.company.app.test
Windows 可执行文件名 app.exe app-test.exe
userData（数据目录） …/app …/app-test
内嵌页的会话分区 persist:web persist:web-test

每一项都要改，漏一个就出问题：漏了 appId，两个版本可能被系统认成同一个应用；漏了 userData，两个版本共用一个数据库；漏了 partition，两个版本共用登录态。

安装包文件名也要带 channel（app-test-setup.exe / app-production-setup.exe），否则分发时最容易拿错。

三、Windows 上 userData 落在安装目录旁

一个和 macOS 不一样的地方：打包后的 Windows 版，数据目录默认在安装目录旁边（<installDir>/data），而不是 %APPDATA%。mac 和开发态则还是用标准的应用支持目录 / 渠道子目录。

这个差异带来一个安装器上的要求：不能默认装到没有写权限的位置（比如 Program Files）。所以 Windows 安装器用”非一键 + 允许改安装目录”的模式，让数据目录总是可写的。

四、真坑一：asar 污染，安装包涨到几个 GB

这是最贵的一个坑。现象是安装包突然变得巨大。

根因是打包器只会自动排除当前构建的输出目录。当产物按平台分目录时（比如输出到 dist/win-x64-test/），同级的兄弟目录——上一个版本的 .app、.dmg、win-unpacked/——不会被自动排除，于是被一起打进了 app.asar。

结果就是 asar 膨胀到 约 2.3 GB，安装包数 GB，NSIS 直接以 exit 1 失败。

修复很简单但必须显式写：让打包配置排除掉整个产物目录（!dist{,/**/*}），不能指望打包器自动处理。顺带还应该在出包前加一道预检，清理散落的中间文件、对意外的顶层路径直接失败——避免”出完包才发现 asar 脏了”这种事后发现。

五、真坑二：跨平台构建禁令

前面讲 sidecar 时提过：随包的采集引擎是按构建机平台嵌入的。所以：

不要在 macOS 上跑 Windows 的打包脚本，也不要在 Windows 上跑 macOS 的。

在 mac 上打 Windows 包，会把 darwin 的运行时打进安装包，用户在 Windows 上首启就报平台不匹配（BUNDLE_PLATFORM_MISMATCH）。各平台在各自的机器 / runner 上出包，是硬要求，不是建议。

六、出包校验：不要信退出码

打包命令”成功退出”不等于产物正确。我们专门写了一个产物校验步骤，检查那些退出码看不出来的东西：

  • asar 卫生（有没有混进不该有的东西）；
  • 可执行文件的可执行位；
  • channel 一致性（产物、文件名、appId 是否都属于同一个 channel）；
  • 随包资源是否齐全。

并且把它挂在出包流程里，两边产物都在的时候必须显式指定校验哪个 channel。核心思想一句话：打包的完整性要用产物本身验证，而不是用构建命令的返回值。

七、诚实的边界

  • 双 channel 的隔离清单是针对我们这套技术栈的（Electron + 内嵌远程页 + 本地数据库 + sidecar）。换栈的话隔离点会变，但”凡是会跨版本共享的状态都要隔离”这个原则不变。
  • 跨平台构建禁令是sidecar 带来的；如果应用不随包平台相关的二进制，跨平台构建在技术上可行——但我们不押这个假设。
  • 产物校验能挡住”打包配置错误”，挡不住”代码逻辑错误”——它是打包层的门禁，不是质量门禁。

总结

  • 双 channel 共存要隔离五样东西：显示名、appId、可执行文件名、userData、会话 partition，外加安装包文件名；
  • Windows 打包版的 userData 在安装目录旁，所以不能默认装到无写权限路径；
  • asar 污染是最大体积坑：打包器只自动排除当前输出目录，必须显式排除整个产物目录，否则安装包能涨到 GB 级；
  • 不能跨平台构建：sidecar 按构建机平台嵌入，跨平台打包会导致平台不匹配；
  • 出包要用产物校验（asar 卫生 / 可执行位 / channel 一致性），不要信退出码。
