Java 后端第一次写 Electron：主进程、预加载、渲染进程的边界

写了七年 Java 后端，我的第一个桌面项目是 Electron。后端的直觉在这里一半有用、一半是坑。这篇文章讲 Electron 三个进程的边界怎么划，以及从后端视角最容易踩的几个点。

一、先建立心智模型

Electron 不是”一个进程里跑前端”，它天然是三层的。用后端的语言类比，会瞬间清晰：

Electron 层 类比 能力
main（主进程） 后端服务 有 Node、能开窗口、能读写文件、能起子进程
preload（预加载） API 网关 / BFF 唯一的桥，运行在渲染页之前
renderer（渲染进程） 浏览器前端 只管界面，没有 Node，跑在沙箱里

关键心智转变是：渲染进程不被信任。它不是你的前端代码，它是”一个可能被远程内容污染的浏览器标签”。所以任何”能力”都不能直接从 renderer 拿——必须经过 preload 这道窄门，由 main 执行。

这和写后端 API 是一样的思路——契约先行、能力收敛，只是这里的”对外接口”是 IPC。

四、把事件当状态传

采集这类长任务会产生大量进度。我们的做法是：main 是唯一的状态源。

  • 启动时 renderer 拉一次快照（snapshot()）；
  • 之后 main 只推事件，renderer 只消费事件；
  • 每个事件同时驱动两件事：更新 UI、更新本地数据库。

这条约束有个直接推论，也是我们踩过的坑：给事件加字段时，必须同时改持久化类型和 renderer 的事件处理。只改一处，UI 和数据库就会静默不一致——这和后端”改了 DTO 忘了改 DAO”是同一类 bug。

五、两个容易翻车的细节

① preload 的依赖要放 devDependencies。

electron-vite 会把 dependencies 里的包外置（不打进 bundle），而 preload 是打进 bundle 的。所以 preload 用到的库如果错放进 dependencies，打包后会找不到。规则一句话：preload-only 的依赖放 devDependencies。

② 改了 preload，typecheck 不够，要用 CDP 验。

类型检查只检查类型，不检查”运行时的 window.api 是不是真的是个对象”。preload 一旦打包方式出错，最典型的表现是 window.api 变成 undefined——TS 完全看不出来。所以改完 preload，要用调试协议连上去，断言 typeof window.api === 'object'。这是运行时验证，不是类型验证。

六、从后端带来的好习惯与坏直觉

有用的：

  • 分层：main / preload / renderer 就是服务 / 网关 / 前端，边界感直接迁移；
  • 契约先行：先定 shared 里的通道与类型，再实现；
  • 失败显式化：错误码 + 中文提示，宁可报错也不返回残缺数据。

是坑的：

  • 想找一个”框架”：Electron 生态里 UI 层很自由，但没有”Spring”式的统一注解框架，别硬套；
  • 想上 ORM：桌面端本地存储用内置能力就够，引 ORM 会带来原生依赖和打包问题（见下一篇）；
  • 想加测试框架：桌面工程没有测试框架，也没有 pnpm test。质量门禁靠”类型检查 + lint + 打包自检”，而不是单元测试——这是刻意的取舍，不是疏漏。

七、诚实的边界

  • 这套边界是安全优先的取向：IPC 走白名单、渲染页无 Node、远程内容无 preload。代价是”想加个功能要改三处”，灵活性换安全。
  • 沙箱和隔离能挡住”渲染页被污染后拿到系统权限”，但挡不住业务逻辑本身的漏洞——安全边界解决的是进程信任问题，不是数据正确性问题。

总结

  • Electron 三层：main（有权限）/ preload（窄门）/ renderer（沙箱、无 Node），用后端类比即”服务 / 网关 / 前端”；
  • 渲染进程不被信任：contextIsolation + sandbox + 关 nodeIntegration 是硬约束；
  • renderer 只走 window.api，通道在 shared 声明、preload 实现、main 处理，禁止泛型透传；
  • main 是唯一状态源：启动拉一次快照，之后只推事件；加事件字段要同时改持久化和渲染层；
  • 两个细节坑：preload 依赖放 devDependencies；改 preload 后要用 CDP 断言 window.api，typecheck 不够；
  • 后端的好习惯（分层 / 契约 / 失败显式化）能迁移；坏直觉（找框架 / 上 ORM / 加测试框架）要克制。
