关灯

从手写核心循环，到 Spring AI / RAG，再到「在真实工程里可控」。重点是可落地的边界，不是 Demo 演示。

共 14 篇。前四篇手写打底，中间七篇落到框架与生产，最后三篇讲工程可控。

一、先手写，再对比框架

  1. 从零实现 Function Calling：一个 39 行的工具注册表
    为了搞懂原理自己实现一遍基础设施。它是 demo，不是生产框架。
  2. 30 行手写一个 ReAct Agent：每一行都看得懂
    整个 Agent 核心就是 30 行 Java，每一行都知道为什么在这。
  3. 自己写 Agent vs Spring AI：210 行和 30 行的取舍
    同一个功能写了两遍，差异本身就是最好的教材。
  4. MCP：工具调用的”JDBC”
    手写一个最小版 Server/Client，看懂这个 JSON-RPC 协议的约定。

二、RAG 与生产清单

  1. RAG 工程实践：切块、向量化、检索与幻觉控制
    一个刚起步的 RAG 场景：FAQ 切块、pgvector 检索、接 LLM，核心在控制幻觉。
  2. Function Calling：让模型输出结构化 JSON
    让模型真正”干活”的前提：它得明确说出要调哪个函数、参数是什么。
  3. Agent 三层架构与 AI 工程化挑战
    从”调单个工具”到”自己决定下一步”，以及从 Demo 到可靠系统要补的课。
  4. Spring AI 实战：把 LLM 接进 Java 应用
    一个完整示例讲对话与工具调用，附踩过的版本坑。
  5. 用 Spring AI 搭一个 FAQ 问答系统：RAG 实战全流程
    完整小项目，把 RAG 全链路（切块→向量化→检索→拼 prompt→幻觉控制）真跑起来。
  6. Agent 从 Demo 到生产：还差什么？可靠性清单 必读
    Demo 能跑，生产怎么上？从可靠性工程视角梳理要补的东西。
  7. Agent 的 Memory 设计：短期上下文与长期记忆 必读
    Memory 是最容易被低估的一层——不是”把历史塞进 prompt”就完事。

三、编排对照与工程可控

  1. 从 SyncTask 到 Agent：编排引擎思想的工程迁移
    做 Agent 时最大的优势不是 Python 也不是 Prompt，而是这套编排经验。
  2. 让 AI Agent 在真实工程里可控：四层约定分工 必读
    难的不是让 AI 写代码，是让它在一周后、换个人接手时依然按同一套约定干活。
  3. 该不该复用第三方库内置的 LLM 能力：一次 ADR 复盘
    库里已经内置了一整套 LLM 能力，为什么不直接用——一次 ADR 式的决策复盘。
