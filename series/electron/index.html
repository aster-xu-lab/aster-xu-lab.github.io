关灯

一个 Java 后端第一次做桌面端：进程边界、无原生依赖、CLI sidecar 爬虫、人机协同反爬、状态与数据建模、密钥与构建发布。按推荐顺序连读即可。

共 32 篇。前四部分是主线，最后一部分是同一条项目线上的工程方法与复盘，可以穿插阅读。

一、进程与依赖

  1. Java 后端第一次写 Electron：主进程、预加载、渲染进程的边界
    写了七年后端，第一个桌面项目。后端的直觉在这里一半有用、一半是坑。
  2. 用 node:sqlite 替掉 better-sqlite3：告别原生模块
    放弃默认答案 better-sqlite3，核心不是性能，而是不想让主进程背上原生模块。
  3. 桌面应用不能留孤儿进程：退出时到底该杀谁
    Electron 退出了，随包的 Chromium 和 JVM 还在跑——进程生命周期不能只靠窗口关闭。

二、采集与反爬

  1. Electron 桌面端爬虫：为什么选 CLI sidecar 而不是 Puppeteer
    随包分发一个 CLI + JVM + Chromium，以及这个选择引出的跨平台构建硬约束。
  2. 反爬可用率对照实验：Amazon 与 eBay 的十倍差距 必读
    同一套代码，Amazon 8%、eBay 90%。十倍差距怎么测出来的，以及哪个”更快的方案”是陷阱。
  3. 爬虫的人机协同：验证码弹框，而不是硬刚
    最难受的不是被拦，是不知道被拦了还是代码坏了——失败分类、人工确认、会话自愈。
  4. 1000 条采集跑完：99.3%、4.18 小时，以及 7 条失败全来自一个 302
    完整链路和引擎路径的差额拆账，以及为什么”失败预算”比失败率更有信息量。
  5. 长跑采集的内存不是调大堆：从 2 GB OOM 到 350 MB 稳态
    最大的垃圾源是一次导航命令顺手构建的 accessibility tree；调参数不是归因。

三、状态、数据与安全

  1. 事件就是状态：用一个事件流驱动 UI 与数据库 必读
    状态一多就容易”界面和库里对不上”。只让一个事件流当真相，两边都是它的投影。
  2. 把商家后台嵌进桌面端：WebContentsView 与登录闸门
    内嵌远程页面还要拿它当登录闸门，”怎么判定登录状态”这个问题看似简单实则全是坑。
  3. LLM Key 不下渲染进程：Electron 里的密钥边界
    API Key 放哪？放渲染进程最方便也最危险。以及为什么”模型建议”必须和”采集证据”分开。
  4. 从 URL 计数到商品实例：一次数据模型重做
    平台身份、任务实例、失败事实分属三层；开发期可以一次性重置，发布后必须显式迁移。
  5. 预填不是填空题：多源合并、来源溯源与可撤销
    预填的产物不是值，而是「值 + 来源 + 删除记录 + 规则版本」。

四、构建、发布与更新

  1. Electron 双 channel 共存与跨平台构建禁令
    测试版和生产版要在同一台机器上并存、互不覆盖——要隔离哪些东西，以及 asar 污染的坑。
  2. 跨平台构建不是一条命令
    两个平台、两套工具链、两份产物；哪些差异必须在构建层解决，哪些不能假装抹平。
  3. 桌面端的签名、公证与混淆加壳：先分清这三件事 必读
    三个词常被混为一谈，但手段、成本、收益差很多。讲清楚”加固”该先做什么。
  4. 签名和公证真的做了以后
    概念落到证书、公证流程和权限位之后，哪些坑才真正出现。
  5. 安装器升级时哪些东西该保留
    升级会先跑旧卸载器；不保护数据目录，就是每升一次丢一次数据。
  6. 桌面端自动更新不是接个 electron-updater 就完了
    服务端版本/制品/策略模型，客户端状态机，以及强制门禁怎么真的拦住写入。
  7. 检查更新与执行更新，不是一个动作
    读与写分开、门禁与中断分开、周期检查与关键操作前复检分开。
  8. 364MB 安装包上传失败：从 multipart 上限到堆内 OOM
    配置上限是 1000MB，失败却在 256MB——根因是上传实现把整包读进了堆。
  9. 包内包外：桌面应用不该从 PATH 找自己的工具
    随包分发还是显式配置；cwd 和 PATH 是开发便利，不是产品行为。

五、工程方法与复盘

  1. 没有测试框架的项目怎么做质量基线
    没有 pnpm test 不等于没有质量门禁——几道门闩各自能挡住什么、挡不住什么。
  2. 给没有测试框架的桌面应用写状态机探针
    用 CDP 驱动真实应用，先断言”被测入口确实被调用过”，避免拿陈旧状态读成通过。
  3. 一次字段名错误，吞掉了所有失败原因
    服务端返回 rtn_code，客户端读 code；成功路径侥幸命中，所有业务失败退化成一个空原因。
  4. ADR 驱动决策：把”不做”也写成可复盘的决策
    一份有用的 ADR 长什么样，为什么它的价值在”为什么不选另一条路”。
  5. 一个月从 0 到演示：排期与降级策略
    演示版和生产版差十倍工期，怎么分开；演示交付里最重要的东西是降级方案。
  6. 写文档也是工程：分类目录与”风险单列”
    二十来份文档的目录约定与写作规范，以及最容易被违反的一条原则。
  7. 把重复工作流沉淀成 Skill 与 Agent
    哪些流程值得沉淀、触发边界怎么划、Skill 过期为什么比没有更糟。
  8. 一套资产，三个宿主：Agent 规则的单一源与生成入口
    从符号链接换到共享源 + 生成薄入口；单一源不是只有一个文件，而是只有一个可编辑的文件。
  9. 跨平台选型：没有零代价的方案，只有扛得住的代价
    包体积、性能、生态三笔账互相牵制；选型不是找没有缺点的方案，而是找缺点扛得住的方案。
  10. 失败要留下证据：采集与上传的失败路径设计
    失败快照、错误码分层、阶段化错误；失败率是结果，失败证据才是下一次修复的输入。
