关灯

一个 Java 后端第一次做桌面端：进程边界、无原生依赖、CLI sidecar 爬虫、人机协同反爬、密钥与构建。按时间顺序连读即可。

主线 10 篇按顺序读；后面 4 篇是同一条项目线上的工程方法论，可以穿插。

一、进程与依赖

  1. Java 后端第一次写 Electron：主进程、预加载、渲染进程的边界
    写了七年后端，第一个桌面项目。后端的直觉在这里一半有用、一半是坑。
  2. 用 node:sqlite 替掉 better-sqlite3：告别原生模块
    放弃默认答案 better-sqlite3，核心不是性能，而是不想让主进程背上原生模块。

二、采集与反爬

  1. Electron 桌面端爬虫：为什么选 CLI sidecar 而不是 Puppeteer
    随包分发一个 CLI + JVM + Chromium，以及这个选择引出的跨平台构建硬约束。
  2. 反爬可用率对照实验：Amazon 与 eBay 的十倍差距 必读
    同一套代码，Amazon 8%、eBay 90%。十倍差距怎么测出来的，以及哪个”更快的方案”是陷阱。
  3. 爬虫的人机协同：验证码弹框，而不是硬刚
    最难受的不是被拦，是不知道被拦了还是代码坏了——失败分类、人工确认、会话自愈。

三、状态与安全

  1. 事件就是状态：用一个事件流驱动 UI 与数据库 必读
    状态一多就容易”界面和库里对不上”。只让一个事件流当真相，两边都是它的投影。
  2. 把商家后台嵌进桌面端：WebContentsView 与登录闸门
    内嵌远程页面还要拿它当登录闸门，”怎么判定登录状态”这个问题看似简单实则全是坑。
  3. LLM Key 不下渲染进程：Electron 里的密钥边界
    API Key 放哪？放渲染进程最方便也最危险。以及为什么”模型建议”必须和”采集证据”分开。

四、构建与外发

  1. Electron 双 channel 共存与跨平台构建禁令
    测试版和生产版要在同一台机器上并存、互不覆盖——要隔离哪些东西，以及 asar 污染的坑。
  2. 桌面端的签名、公证与混淆加壳：先分清这三件事 必读
    三个词常被混为一谈，但手段、成本、收益差很多。讲清楚”加固”该先做什么。

配套工程笔记

同一条项目线上的方法论，可穿插阅读：

  • 没有测试框架的项目怎么做质量基线
    没有 pnpm test 不等于没有质量门禁——几道门闩各自能挡住什么、挡不住什么。
  • ADR 驱动决策：把”不做”也写成可复盘的决策
    一份有用的 ADR 长什么样，为什么它的价值在”为什么不选另一条路”。
  • 一个月从 0 到演示：排期与降级策略
    演示版和生产版差十倍工期，怎么分开；演示交付里最重要的东西是降级方案。
  • 写文档也是工程：分类目录与”风险单列”
    二十来份文档的目录约定与写作规范，以及最容易被违反的一条原则。
