6000万订单表迁移到分片：双写 + 灰度 + 回补 + 回滚全流程

迁移的难点：不能停服

or_sales_info 上线前约 6000 万存量数据，要从单表改成分片表。最难的不是写分片代码，而是存量数据怎么在业务不停服的情况下迁移过去。

我写了一个综合演练，模拟完整迁移流程（造数 → 双写 → 回补 → 灰度 → 校验 → 性能 → 回滚），下面拆解每一步。这是本地演练，不是生产执行；生产迁移复盘见《分库分表迁移复盘：从分片键决策到无停机上线》。

整体流程

1. 造数：生成存量单表数据

模拟 6000 万存量（演示用小量，逻辑等价）。or_sales_info 已确认单号主分片（业务事件都按单号），迁移到单号 hash 分片表。

2. 双写：新老表同时写入（核心）

双写是迁移安全的核心——它保证灰度/回滚随时可切，数据不丢。

6. 性能对比：带分片键 vs 广播

数据量越大、分片越多，带分片键的优势越明显（只查目标单表，不广播）。所以业务事件(创建/发货/取消/签收)都按单号精准路由，这是单号主分片的核心价值。

关键结论

步骤 要点
双写 新订单写老+新，保证可回滚
回补 批量+幂等，扫存量搬过去
灰度 按平台切读流量，影响可控
校验 数量/分布对账
性能 单号分片只查目标分片（带分片键零广播）
回滚 双写让回退零成本

双写 + 灰度 是”不停服、可回滚”迁移的两大支柱。本项目是单号 hash 分片，迁移需要 rehash/回补；双写 + 灰度让迁移可回滚。
